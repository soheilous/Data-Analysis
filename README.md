# دیدبان — پایش پیج‌ها و هشتگ‌های اینستاگرام

رابط فارسی راست‌چین با Next.js و MUI، سرور FastAPI و دیتابیس SQLite. این مرحله شامل ورود، تعریف چند منبع، دریافت پست و کامنت، جستجو، خروجی و مدیریت اجراهاست. هیچ مدل یا سرویس AI نصب یا اضافه نشده است.

## نصب

Python 3.11 یا جدیدتر و Node.js 20.9 یا جدیدتر لازم است. در پوشه پروژه:

```powershell
py -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
cd frontend
npm ci
cd ..
```

## اجرا

در یک پنجره PowerShell در پوشه پروژه:

```powershell
.\.venv\Scripts\python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

در پنجره دوم:

```powershell
cd frontend
npm run dev
```

سپس http://127.0.0.1:3000 را باز کنید. برای نسخه بهینه به‌جای `npm run dev` ابتدا `npm run build` و سپس `npm start` را اجرا کنید. فقط یک worker برای سرور استفاده کنید و هنگام جمع‌آوری reload نکنید. هر دو سرور فقط روی سیستم محلی گوش می‌دهند. صفحه قدیمی HTML در جریان اصلی استفاده نمی‌شود.

## نحوه استفاده

پروژه جدید را بزنید. در مرحله اول روش جمع‌آوری را انتخاب کنید. روش مستقیم نام کاربری و رمز می‌گیرد. در روش «جمع‌آوری با مرورگر»، بعد از شروع اجرا در پنجره اینستاگرام وارد شوید. این روش فقط پست‌ها و کامنت‌هایی را جمع می‌کند که اینستاگرام در مرورگر نمایش می‌دهد. اتصال حساب فقط با شروع اجرا بررسی می‌شود؛ عبور از مرحله اول به معنی ورود موفق نیست. در مرحله دوم عنوان پروژه، نام شرکت‌ها و تگ‌های جست‌وجو را وارد کنید. هر مورد را با Enter یا دکمه افزودن به فهرست اضافه کنید. نام شرکت‌ها در پروژه ثبت می‌شوند و تگ‌ها برای پیدا کردن پست‌ها استفاده می‌شوند. مرحله سوم سقف پست هر منبع، سقف کامنت هر پست و دریافت اختیاری لایک‌کننده‌ها را تنظیم می‌کند.

در روش مستقیم، دریافت با Instaloader انجام می‌شود. پست‌های تکراری بین پیج‌ها و هشتگ‌ها در یک اجرا یک‌بار ذخیره می‌شوند؛ منبع ثبت‌شده، اولین منبعی است که پست را پیدا کرده است. سقف پست برای هر منبع قبل از حذف تکراری‌ها اعمال می‌شود. کپشن، صاحب پست، منبع، زمان انتشار، کامنت و تعداد لایک ثبت می‌شوند. پاسخ‌های تودرتو جداگانه دریافت نمی‌شوند. داده‌ها به ترتیب پست ذخیره می‌شوند و شکست اجرا نتایج قبلی آن را پاک نمی‌کند. در خطای ورود، چالش امنیتی یا محدودیت اینستاگرام، خطای پاک‌سازی‌شده در گزارش نمایش داده می‌شود؛ دور زدن محدودیت انجام نمی‌شود. دسترسی کامل به همه پست‌های هشتگ و کامنت‌ها تضمین نشده است. این رابط غیررسمی است و باید مجوز و شرایط استفاده اینستاگرام رعایت شود.

دکمه مشاهده، پست‌ها، کامنت‌ها، جستجو، گزارش و دانلود CSV/Excel را باز می‌کند. اطلاعات اجراهای قبلی با دیتابیس فعلی سازگارند و پاک نمی‌شوند. دکمه حذف، خود اجرا، تنظیمات، گزارش، نتایج و خروجی‌های CSV/Excel محلی آن را پس از تأیید حذف می‌کند. تا پایان اجرای فعال، حذف غیرفعال است. نسخه‌های Drive، بکاپ‌ها و دانلودهای قبلی باقی می‌مانند.

اگر پس از شروع، اینستاگرام کد دومرحله‌ای بخواهد، اجرا تا پنج دقیقه منتظر می‌ماند. کد را در پنجره همان اجرا وارد کنید. اگر پنجره را بسته‌اید، از «وارد کردن کد» در تاریخچه استفاده کنید. اگر اینستاگرام تأیید امنیتی بخواهد، «ورود در مرورگر و ادامه» را انتخاب کنید. در پنجرهٔ اینستاگرام با همان حساب وارد شوید و تأیید را کامل کنید. پس از پذیرفته شدن نشست، همان اجرا دریافت مستقیم را ادامه می‌دهد. مرورگر از Chromium مربوط به Playwright استفاده می‌کند. اگر نصب نیست، `.\.venv\Scripts\python -m playwright install chromium` را اجرا کنید.

در روش «دریافت همهٔ هشتگ‌ها با instagrapi»، یک ورود برای کل اجرا انجام می‌شود. سقف پست برای هر هشتگ و سقف کامنت برای هر پست اعمال می‌شود. برای هر هشتگ ابتدا بخش پست‌های اخیر بررسی می‌شود. اگر خالی باشد، بخش پست‌های برتر بررسی می‌شود. تگ بدون نتیجه در گزارش ثبت می‌شود و برنامه به تگ بعدی می‌رود. پست تکراری فقط در اولین هشتگی که آن را برگرداند ذخیره می‌شود.

در روش مرورگر، «پیج‌های اینستاگرام» نام کاربری پیج شرکت را می‌گیرد. نشست در پروفایل محلی دیدبان در `%LOCALAPPDATA%/Didban/instagram-profile` نگه داشته می‌شود. پست‌ها یکی‌یکی در تب جدا باز می‌شوند. دیدبان فیلدهای شناخته‌شدهٔ پاسخ‌های شبکه را استخراج می‌کند و در صورت نیاز متن کامنت‌های قابل مشاهده را بررسی می‌کند. پست‌های ثبت‌شده با شناسهٔ یکسان دوباره باز نمی‌شوند، مگر گزینهٔ به‌روزرسانی را فعال کنید. اگر اینستاگرام ورود یا تأیید تازه بخواهد، باید آن را در پنجرهٔ رسمی انجام دهید.

در مرحلهٔ «روش جمع‌آوری»، حالت «آیدی پیج + تگ» پست‌های پیج‌های مشخص را تا سقف بررسی هر پیج باز می‌کند و پستی را ثبت می‌کند که در کپشنش دست‌کم یکی از تگ‌ها باشد. حالت «فقط تگ از دیسکاور» بدون نام پیج، هر تگ را در جست‌وجوی اینستاگرام بررسی می‌کند و سقف پست برای هر تگ جداگانه اعمال می‌شود. پروژه‌های قدیمی تا زمان ذخیرهٔ دوباره با تنظیمات قبلی اجرا می‌شوند.

## اطلاعات ورود

رمز، نام حساب ورود و کد دومرحله‌ای وارد SQLite، خروجی و بکاپ نمی‌شوند. پروفایل نشست مرورگر خارج از پروژه و بکاپ نگه داشته می‌شود. رمز و کد پس از پذیرفته‌شدن درخواست از فرم پاک می‌شوند و داده ورود تا پایان اجرای مربوط فقط در حافظه استفاده می‌شود. نام پیج‌های هدف در تنظیمات پروژه ذخیره می‌شود. اطلاعات ورود را در سورس یا Drive قرار ندهید. مقدارهای قدیمی غیرحساس در ابتدای scraper.py کامنت شده‌اند؛ رمز فایل اصلی در تحویل‌ها وجود ندارد.

## Google Drive اختیاری

Google Drive for desktop را با همان حساب مشترک وارد کنید و پیش از اجرای سرور متغیر زیر را با مسیر واقعی پوشه همگام‌شونده تنظیم کنید:

```powershell
$env:DRIVE_OUTPUT_DIR='G:\My Drive'
```

اگر گزینه Drive فعال باشد، پس از اجرای موفق CSV، Excel و بکاپ سازگار SQLite در `Marketing Intelligence/<project-id>/<run-id>` (برای اجراهای مستقل در پوشهٔ `اجراهای مستقل`) کپی می‌شوند. پیام کپی موفق به معنی تأیید ارسال ابری نیست؛ ارسال توسط Drive desktop انجام می‌شود. اشتراک‌گذاری جداگانه لازم نیست. دیتابیس فعال `data/project.sqlite` را داخل Drive قرار ندهید. برای بازیابی، سرور را ببندید و بکاپ SQLite را جایگزین این فایل کنید. بکاپ شامل همه اجراهای ذخیره‌شده است.

## ساخت فایل اجرایی ویندوز

روی سیستم سازنده، در پوشهٔ پروژه این دستور را اجرا کنید:

```powershell
.\build-exe.ps1
```

اسکریپت روی سیستم سازنده به Python، Node.js و دسترسی به دانلود وابستگی‌ها نیاز دارد. خروجی `dist/Didban.exe` شامل رابط، سرور پایتون و مرورگر Chromium است. روی سیستم مقصد فقط فایل EXE را باز کنید. پنل در مرورگر پیش‌فرض باز می‌شود و برای توقف سرور، در پنجرهٔ دیدبان `Ctrl+C` بزنید.

دادهٔ نسخهٔ اجرایی در `%LOCALAPPDATA%/Didban/data` نگه داشته می‌شود. برای انتقال دادهٔ قبلی، وقتی هر دو نسخه بسته‌اند، بکاپ SQLite را در این پوشه با نام `project.sqlite` قرار دهید. دیتابیس و نشست حساب داخل EXE قرار نمی‌گیرند.

برای بررسی بسته با دیتابیس موقت، `.\dist\Didban.exe --self-test` را اجرا کنید.

نسخهٔ کم‌حجم وابسته به Chrome نصب‌شده را با `.uild-exe-chrome.ps1` بسازید. خروجی `dist/Didban-Chrome.exe` است و برای جمع‌آوری به Google Chrome نصب‌شده و قابل اجرا نیاز دارد. این نسخه از پروفایل جداگانهٔ دیدبان برای نشست استفاده می‌کند. برای بررسی بسته می‌توان `.\dist\Didban-Chrome.exe --self-test` را اجرا کرد.

## ساختار دیتابیس

پست‌ها در جدول `posts`، کامنت‌ها در جدول `comments` و دیده‌شدن هر پست در هر اجرا (با تعداد لایک همان زمان) در جدول `run_posts` ذخیره می‌شوند. فیلدهای بدون ستون جداگانه در ستون JSON به نام `extra` نگه داشته می‌شوند. در اولین اجرای این نسخه، داده‌های JSON قبلی به این جدول‌ها منتقل می‌شوند و جدول‌های قدیمی با نام‌های `results_legacy` و `project_posts_legacy` باقی می‌مانند. پس از این انتقال، نسخه‌های قدیمی برنامه را روی همان دیتابیس اجرا نکنید.

## بررسی

`npm run build` در پوشه frontend، ساخت نسخه بهینه و بررسی TypeScript را انجام می‌دهد. آزمایش واقعی دریافت از اینستاگرام به حساب مجاز و دسترسی شبکه نیاز دارد؛ موفقیت ساخت رابط به معنی موفقیت جمع‌آوری نیست.

آزمایش‌های آفلاین جمع‌آوری: `.\.venv\Scripts\python -m unittest discover -s tests -v`. این تست‌ها ورود دومرحله‌ای، پاک‌سازی اطلاعات ورود، هشتگ، سقف کامنت و حذف پست تکراری را بدون اتصال به اینستاگرام بررسی می‌کنند.

در بخش «فایل‌های Google Drive» فهرست فایل‌های خروجی و بکاپ دیدبان، از جمله فایل‌های ساختار قبلی، قابل مشاهده است. می‌توانید نام فایل را با حفظ پسوند تغییر دهید یا آن را حذف کنید. این تغییرات پس از همگام‌سازی در Drive مشترک نیز اعمال می‌شوند.
